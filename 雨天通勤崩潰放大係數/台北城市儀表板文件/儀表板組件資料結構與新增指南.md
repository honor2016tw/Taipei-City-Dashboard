# 臺北城市儀表板 - 資料結構與新組件開發指南

這份文件介紹了臺北城市儀表板 (Taipei City Dashboard) 的資料庫結構、前端組件對應關係，以及資料流。如果你需要開發或插入一個新的圖表組件 (Component) 進入這個儀表板，請參考此指南，這份文件非常適合作為上下文丟給另一個 LLM 或 Agent 閱讀。

## 1. 核心資料庫結構 (PostgreSQL)

儀表板的設定與組件皆由資料庫驅動。核心設定分散在以下幾個 Tables 中，每個組件 (Component) 共通的識別碼為字串 `index`。

*   **`components`**: 定義組件的基本對應目錄 (`id`, `index`, `name`)。
*   **`query_charts`**: 負責圖表的核心設定與**「撈取資料的 SQL 邏輯」**。前端會依據此表的設定呼叫後端取得資料。
    *   `index`: 組件識別碼。
    *   `city`: 適用區域 (例如 `taipei`, `newtaipei`, `metrotaipei`)。同一組件在不同區域會有不同的 query 邏輯。
    *   `query_type`: 決定資料回傳與轉換的格式 (如 `two_d`, `three_d`, `time`, `percent`, `map_legend`)。
    *   `query_chart`: **最重要**，這段 SQL 會在後端直接執行。你必須在 SQL 內將欄位 alias 成 `x_axis`, `y_axis`, `data`, `icon` 等以符合格式。
    *   `short_desc`, `long_desc`, `use_case`: 顯示在前端「詳細資訊 (MoreInfo)」卡片中的文字。
    *   `source`, `links`, `contributors`: 資料來源標示與連結。
    *   `map_config_ids`, `map_filter`: 控制該圖表與地圖圖層的聯動與篩選行為。
*   **`component_charts`**: 定義組件在前端的顯示與視覺設定。
    *   `types`: 字串陣列，決定前端載入哪個 Vue Component (例如 `{BarChart, ColumnChart}`，如果有多個會產生 tab 切換)。
    *   `color`: 圖表的色碼陣列 (例如 `{#24B0DD,#56B96D}`)。
    *   `unit`: 圖表的單位 (例如 `輛`, `%`, `仟人`)。
*   **`component_maps`**: (如有空間資料才需設定) 定義 Mapbox 空間地圖圖層。
    *   `type`: 圖層類型 (`circle`, `line`, `symbol`, `fill` 等)。
    *   `source`: 資料來源 (如 `geojson`)。
    *   `paint`: Mapbox GL JS 的 paint style JSON。
    *   `property`: 點擊地圖圖徵時跳出的 Popup 所顯示的屬性欄位映射 (Key-Name 格式)。
*   **`dashboards`**: 負責定義一個「儀表板頁面」會包含哪些組件 (透過 array mapping 到 component IDs)。

## 2. 前後端資料契約 (Data Contract)

依據 `query_charts.query_type` 的不同，前端的圖表類型 (如 `BarChart`, `ColumnChart` 等) 會預期收到特定結構的 JSON。SQL (`query_chart`) 的產出必須配合：

*   **`two_d`**: 適合 `BarChart` (橫向長條圖), `DonutChart`。
    *   期望 SQL 欄位：`x_axis`, `data` (有時包含 `y_axis`)。
*   **`three_d` / `percent`**: 適合 `ColumnChart` (縱向長條圖), `BarPercentChart` (百分比)。
    *   期望 SQL 欄位：`x_axis` (通常是分類), `y_axis` (系列名稱), `data` (數值)。
*   **`time`**: 適合折線圖 (`TimelineSeparateChart`) 等。
    *   期望 SQL 欄位：`x_axis` (需為 timestamp 字串), `y_axis`, `data`。
*   **`map_legend`**: 適合 `MapLegend` (圖例組件)。
    *   常直接以 static SQL 返回圖例結構，例如 `SELECT '自行車路網' as name, 'line' as type`。

## 3. 最小插入新組件 (Component) 必須具備的資訊清單

若要請 LLM 或開發者最小化地建立並插入一個新圖表組件，必須提供以下 **4 大區塊** 的具體參數：

### 區塊 A: 基礎資訊與文案 (Metadata)
1.  **`index`** (英文代號，必填): 唯一識別碼，如 `new_traffic_score`。
2.  **`name`** (中文名稱，必填): 如 `新交通評分`。
3.  **`city`** (區域，必填): 通常為 `taipei` 或 `metrotaipei`。
4.  **`source`** (資料提供者): 如 `交通局`。
5.  **`short_desc`** (卡片短敘述): 例如 `此圖顯示各區域的交通評分。`
6.  **`long_desc`** (詳細說明): 用於解釋指標意義。
7.  **`use_case`** (情境應用): 政府或市民能如何運用這個數據。

### 區塊 B: 圖表視覺設定 (對應 component_charts)
1.  **`types`** (前端組件類型，必填): 指定要使用的 Vue 組件 (參考原始碼定義)。
    *   *常用圖表*: `BarChart`, `ColumnChart`, `DonutChart`, `BarPercentChart`, `MapLegend`。
2.  **`color`** (顏色陣列，必填): 定義資料系列的色碼，如 `{#5a9cf8, #494b4e}`。
3.  **`unit`** (單位): 數值單位字串，無則填 `\N`。

### 區塊 C: 資料查詢邏輯 (對應 query_charts)
1.  **`query_type`** (格式類型，必填): 指定為 `two_d`, `three_d`, `time`, 或是 `percent`。
2.  **`query_chart` (SQL 邏輯，最關鍵)**:
    *   必須提供完整的 SQL `SELECT` 語法。
    *   請確保 SELECT 的欄位別名符合該 `query_type` 預期的命名。
    *   *範例*: `SELECT 站點名稱 AS x_axis, '評分' AS y_axis, ROUND(分數) AS data FROM 交通評分資料表`

### 區塊 D: 地圖設定 (對應 component_maps) —— *無地圖圖層則免填*
若這個組件包含地理資訊且要在地圖 (MapView) 上顯示：
1.  **`type`**: 指定 mapbox 類型 (如 `circle`, `line`)。
2.  **`source`**: 通常設為 `geojson`，前端會去抓同名 geojson 檔。
3.  **`paint`**: mapbox GL 的樣式語法 JSON (如透明度、半徑、顏色條件)。
4.  **`property`**: 點擊地圖 Popup 要顯示的欄位 JSON，如 `[{"key": "score", "name": "評分"}]`。
5.  **地圖交互過濾 (`map_filter`)**: 當點擊長條圖時是否要過濾地圖上的資料？例如 `{"mode":"byParam","byParam":{"xParam":"zone"}}`。

>
