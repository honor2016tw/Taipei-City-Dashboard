### 1.2 建議 chart_data

主排行用 `BarChart`，資料可以是：

```json
[
  {
    "name": "",
    "data": [
      { "x": "木柵", "y": 55 },
      { "x": "萬芳社區", "y": 60 },
      { "x": "南勢角", "y": 67 }
    ]
  }
]
```

子指標拆解用 `ColumnChart`，資料可以是：

```json
[
  { "name": "取車", "data": [20, 33, 50] },
  { "name": "還車", "data": [100, 100, 100] },
  { "name": "公車", "data": [33, 43, 49] },
  { "name": "覆蓋", "data": [93, 78, 85] }
]
```

搭配：

```json
"categories": ["木柵", "萬芳社區", "南勢角"]
```

### 1.3 如果要保留我們現在的捷運 SVG 路網

官方現有 `MetroChart` 不適合，因為它是「車廂擁擠程度線性圖」，不是地理路網圖。

需要新增：

```text
src/dashboardComponent/components/MetroServiceChart.vue
src/dashboardComponent/assets/chart/MetroServiceChart.svg
src/dashboardComponent/utilities/chartTypes.ts
src/dashboardComponent/DashboardComponent.vue
```

並在 `returnChartComponent` 補：

```text
case "MetroServiceChart":
  return svg ? MetroServiceChartSvg : MetroServiceChart;
```

這樣才能在 `chart_config.types` 寫：

```json
["MetroServiceChart", "BarChart", "ColumnChart"]
```

### 1.4 最符合官方設計語言的視覺調整

本案若嵌入官方儀表板，應調整：

- 卡片背景使用 `#282a2c`。
- 圓角改 5px。
- 字體使用 Microsoft JhengHei / Open Sans 系列。
- 標題不要超過一行，必要時縮短成「最後一哩服務健康度」。
- 主色不要自定太多，使用官方 highlight 藍 + 指標色。
- 站點顏色建議：

```text
0-49  #ef6f6c  接駁失效風險高
50-64 #f4b942  服務偏弱
65-79 #7ea1ff  需觀察
80+   #39c5bb  服務穩定
```

## 2. 新組件上架檢查表

### 2.1 Config 層

- `index` 唯一。
- `name` 短，適合卡片 header。
- `short_desc` 可在 preview 卡讀懂。
- `long_desc` 說清楚公式與資料來源。
- `use_case` 寫民眾與政府怎麼用。
- `links` 放 TDX / GeoJSON / 方法文件。
- `city` 用 `metrotaipei`。
- `time_from` 若即時，用 `current`。
- `update_freq` 建議 5。
- `update_freq_unit` 建議 `minute`。

### 2.2 Chart 層

- `chart_config.types[0]` 是預設圖。
- 每個 type 都必須在 `DashboardComponent.vue` 註冊。
- `color.length` 要足夠支援 series 數。
- `unit` 不要放太長，通常 1-3 字。
- 有 grouped chart 時要提供 `categories`。

### 2.3 Data 層

- `two_d`：`[{ data: [{x, y}] }]`。
- `three_d`：`[{ name, icon, data: [] }] + categories`。
- `time`：`[{ name, data: [{x: ISO time, y}] }]`。
- `map_legend`：`[{ type, icon, name, value }]`。

### 2.4 Map 層

- GeoJSON 要放到 `/mapData/{index}.geojson`。
- `map_config.index` 要跟檔名一致。
- `property` 的 key 要存在於 GeoJSON feature properties。
- `circle-color` 可用 Mapbox expression。
- 如果有 filter，chart 的 x label 要能對到 map property。

### 2.5 UX 層

- 卡片內不要放長段文字。
- 詳細方法放 MoreInfo / long_desc。
- 排行圖最多 10-12 筆。
- Tooltip 顯示單位。
- MapLegend 要能說明顏色。
- 失敗/無資料狀態要允許 `chart_data = null`。

## 3. 本案推薦落地路線

### Phase 1：不改核心前端

產出官方 schema：

```text
component_config.json
chart_data.json
metro_last_mile_station_health.geojson
metro_route_lines.geojson
```

使用既有 chart：

```text
BarChart + ColumnChart + MapLegend
```

優點：

- 幾乎不用改官方 FE。
- 能進 DashboardView / MapView。
- 能用官方 MoreInfo、Embed、History、MapPopup。

限制：

- Dashboard 卡片內不會有我們目前那種完整捷運路網 SVG。
- 捷運路網會在 MapView 裡呈現，而不是 chart 卡內呈現。

### Phase 2：新增原生 MetroServiceChart

新增 Vue chart component，吃 `series` 或額外 `chart_data.metro_routes`，在卡片內畫簡化路網。

優點：

- 保留目前路網視覺。
- 更像專案特色。

成本：

- 要改 `DashboardComponent.vue`、`chartTypes.ts`、新增 chart icon。
- 要定義新的 chart_data contract，後端也要配合。

### Phase 3：加歷史與情境濾鏡

先累積 `last_mile_service_history`，再做：

```text
同站同時段健康度趨勢
尖峰/離峰比較
雨天/非雨天情境比較
```

不要一開始把雨天因果倍率做成主指標。
