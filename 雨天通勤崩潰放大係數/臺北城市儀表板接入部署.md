## 資料庫匯入順序

請在專案根目錄執行。

```bash
cd /home/patrick/Projects/OpenMAIC
```

先匯入 dashboard data DB schema：

```bash
docker exec -i postgres-data psql \
  -U postgres \
  -d dashboard \
  < Taipei-City-Dashboard-DE/dags/proj_city_dashboard/metro_last_mile_service_health/table_schema.sql
```

若要立刻看到資料，可匯入目前快照 seed：

```bash
docker exec -i postgres-data psql \
  -U postgres \
  -d dashboard \
  < Taipei-City-Dashboard-DE/dags/proj_city_dashboard/metro_last_mile_service_health/seed_current_data.sql
```

再匯入 dashboard manager component 設定：

```bash
docker exec -i postgres-manager psql \
  -U postgres \
  -d dashboardmanager \
  < Taipei-City-Dashboard-DE/dags/proj_city_dashboard/metro_last_mile_service_health/component_config.sql
```

匯入後重啟 BE/FE，或至少讓 BE 重新讀取資料庫：

```bash
docker restart dashboard-be dashboard-fe
```

若 FE 是 production build，請重新 build：

```bash
cd Taipei-City-Dashboard-FE
npm install
npm run build
```

## Airflow 啟用

新增 DAG：

```text
metro_last_mile_service_health
```

排程：

```text
*/5 * * * *
```

此 DAG 會：

1. 抓 TDX 捷運站、YouBike 站位與可用量、公車站位與 ETA。
2. 以每個捷運站 500 公尺半徑建立最後一哩接駁圈。
3. 寫入 `metro_last_mile_service_health` current table。
4. 追加寫入 `metro_last_mile_service_health_history` history table。
5. 如果 Airflow 容器能看到 FE mapData 目錄，會同步輸出站點 GeoJSON。

若 Airflow 容器中 FE mapData 路徑不是預設值，請設定：

```bash
DASHBOARD_FE_MAPDATA_DIR=/opt/Taipei-City-Dashboard-FE/public/mapData
```

## 地圖交叉比對

本組件使用官方既有 `map_filter`：

```json
{
  "mode": "byLayer",
  "byParam": null
}
```

圖表的 x 軸是：

```text
捷運路線｜捷運站
```

組件內部會把資料拆成捷運路線選單。使用者點擊任一路線時，元件會呼叫官方前端既有 `filterByLayer`，保留同名圖層，因此會同時保留：

```text
該線捷運路網 line layer
該線捷運站 circle layer
```

這就是本版的地圖交叉比對，不需要修改 `mapStore.js`。

## 計算邏輯

```text
ServiceHealth(s,t) =
100 * (
  0.30 * BikePickupAvailability
+ 0.25 * BikeReturnAvailability
+ 0.30 * BusReliability
+ 0.15 * CoverageResilience
)
```

其中：

```text
s = 捷運站
t = 即時快照時間
空間單位 = 捷運站 500 公尺接駁圈
```

子指標：

```text
BikePickupAvailability = 500m 內 YouBike 可借車比例中位數，並扣除離線站點懲罰
BikeReturnAvailability = 500m 內 YouBike 可還空位比例中位數，並扣除離線站點懲罰
BusReliability         = 公車 ETA 中位數與異常狀態率合成
CoverageResilience     = YouBike 站點數與公車站點數合成的替代接駁覆蓋
```

狀態門檻：

```text
80-100 = 穩定
65-79  = 需觀察
50-64  = 偏弱
0-49   = 風險高
```
